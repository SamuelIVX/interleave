# 81 — Aliased source instructions in symmetry DPOR

## TL;DR

interchangeable group has the same identity-alias partition. Preserve the existing DPOR sleep

The two coupled contracts below ship together: action-identity eligibility and sleep-context

superseded only for the layouts accepted here.

## Identity and eligibility contract

1. For each original owner, map each instruction object by identity to its **first occurrence**
   in that owner's immutable step list. All positions sharing that object have the same token.
   Different objects retain different tokens even when their semantic shapes are equal.
2. The owner's alias partition is the ordered vector of these first-occurrence positions.
   For example `[A,B,B,C]` gives `[0,1,1,3]`; `[A,B,C,D]` gives `[0,1,2,3]`.
3. For DPOR only, require equal partition vectors within each existing `SourceSymmetry.groups`
   group. Reject a mismatch before traversal. Retain the conservative whole-run rejection rather
   than silently changing the requested interchangeable groups or weakening the action relation.
4. Fixed owners need no cross-owner alias comparison. Cross-owner object reuse still fails the
   existing trusted instruction owner-binding check. Existing forward-target, typed-local,
   structural/property and no-tid constraints remain authoritative.
5. DFS/static POR/CBS retain their existing eligibility. `freshCopy` recertifies the same bound
   immutable program; `clear` drops coverage without changing its action dictionary.

## Transport and preservation contract

At orbit lookup, encode each sleep entry as `(canonical owner, first occurrence of its action)`.
Use the same whole-frame permutation as the value key. Copy token sets and compare exact equality;
retain all-asleep normalization and the ordinary DPOR subset-antichain behavior unchanged.

For a certified owner permutation, equal structural instruction lists map each PC to an equal
execution shape, while equal alias partitions ensure that two positions reference the same action
object iff their mapped positions do. Thus the mapping preserves both positive and negative sleep
membership tests at every current PC, including stale entries. Distinct identities cannot merge:
first-occurrence labels are injective over an owner's instruction objects. Owner mapping is also
bijective. Equal mapped token sets therefore identify corresponding sleeping actions; they do not
claim subset coverage or search over stabilizer permutations.

Trusted SourceInstruction uses identity equality, immutable behavior and complete footprints.
Existing structural certification already preserves enabledness, effects, forward control,
failures/cutoffs and property inputs under the same owner permutation. Alias certification adds
the missing equality relation used by `SleepSet.contains`; it does not alter execution or prune
additional classes by assuming semantically equal objects are identical. Actual traversal, traces,
source locations and replay retain original IDs and the original recomposed Program.
